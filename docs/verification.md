## v1.0.8 添付ドラッグの残留対策（2026-11-11）

**訂正: 以下は撤回済みの試行記録です。v1.0.9では補助通知処理を除去しました。添付不具合を修正できたことを示す検証ではありません。**

- 確認済み: 拡張はファイルイベントを隣のiframeへ転送していない。通常の並べ替えはFilesを除外する。従来、親・子iframe間のファイルドラッグ終了を補完する処理はなかった。
- 仮説: iframeをまたいだ移動やOS側キャンセルで、先に入ったChatGPTドキュメントが離脱を受け取らず添付用の表示を残す。ユーザー報告と一致する可能性はあるが、実ChatGPTでの原因確定はできていない。
- 対策: Files付きdragenterを受けたターゲットだけを追跡。別の登録ドキュメントへの移動、終了、Escape、ドラッグ終了後のpointermove、ファイル選択完了・キャンセルで、観測した回数だけdragleaveを通知する。dropの転送、ファイル内容取得、入力・添付の書き換え、イベント停止は行わない。drop後の処理はネイティブ処理後に遅延し、新しいドラッグが始まった場合は古い終了処理を捨てる。
- 登録は親と同一オリジンの会話iframeのみ。子内にある任意の第三者iframeへはアクセスしない。画面移動・タブ終了時にリスナーを解除する。
- 自動試験は簡易イベントモデルでの回帰検証。ChatGPTの内部実装を再現したものではない。親→子→隣接、入れ子要素、領域外、反復、Escape、drop後、新規ドラッグとの競合、file input change/cancel、通常のリンク・並べ替え、ドキュメント破棄、入力・既存添付の不変を検査。
- 実Chromeは既存ページとファイルinputの存在を読み取り確認。対象会話に未送信入力があり、添付の選択・アップロード・リロードは未実施。元の不具合の再現、対策後の実DnD、OS選択ダイアログのキャンセル、実添付の成功・隣接画面の復帰は未検証。
- 境界線はboardの非操作擬似要素。board位置の変更に追従する。表示切替・180/340/520px・幅固定を自動検査。実画面の見た目は未確認。

## v1.0.9 完了前レビューによる撤回

追加した2ケースは、v1.0.8の実装を実行していずれも失敗しました。

1. dragleaveで `event.dataTransfer?.types.includes('Files')` を要求するハンドラーでは、dataTransferなしの通知は無視され、nativeDepthが1のまま残りました（期待0）。
2. 最初にdragenterを受けたDOMノードを切断すると、そのノードへdispatchしたdragleaveは文書に伝播せず、同じくnativeDepthが1のまま残りました。

前回のハーネスは全dragleaveを無条件で処理し、切断ノードも文書へ伝播するよう模しており、検証が不十分でした。追加の2ケースでこの不足を確認したため、v1.0.9では補助通知処理を撤回しました。

実ファイルを渡さない空の通知が各サイトで受理される保証はなく、合成イベントの拒否やターゲット固有のカウンターにも依存します。Filesの偽装、ダミーファイル、偽drop、文書全体への無条件の解除操作は追加していません。ChatGPT本来の公開操作で残留を解除する手段は未確認のため、補助通知とリスナーを撤去しました。実ファイル・隣接タブへの転送、既存入力・添付の変更、リロードは行っていません。

最終251テストは非干渉・並べ替え・境界線等の回帰確認です。添付不具合の解消を意味しません。必要な次の検証は、実入力のない利用者指定の検証状態で、OSファイルドラッグ／選択キャンセルと対象・隣接iframeの表示変化を再現することです。
