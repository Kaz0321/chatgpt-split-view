# 既投入テキストの再表示調査（2026-11-17）

ベース: `fix/native-project-controls-v1018` / `21f5348`（manifest 1.0.18）。独立した `fix/draft-replay` 作業ツリーで修正。実行中のChromeの版は未確認。

## 再現した経路

`drafts.connect().attempt()` が同一文書内の入力欄DOM差し替えで `done=false` に戻り、空の新入力欄へ `pane.draft` を再挿入する。合成画面で「入力を記録→本体が入力欄をクリア→input通知前にDOM差し替え→attempt/capture」の順序を実行し、修正前は投入済み相当の文字が復活した。未成立の送信や単なる再描画でも同じDOM変化はあり得るので、送信成功の証拠とは扱わない。

## 最小修正

一度処理した入力欄が同一文書で置き換わった場合は新入力欄の値を優先し、保存文字の自動再挿入をしない。保存値と旧入力欄に残った異なる文字は、不確実な下書きとして既存の `draftBackups` に保持する。初回文書ロードと遅い初期描画の復元は維持。送信ボタン・Enterを監視して削除する処理、メッセージ送信、本文や添付の読み取りは追加しない。

## 検証と制限

textareaとrich editor、クリア通知あり/なし、送信失敗相当の文字残留、空/非空の差し替え、遅延した旧DOM input、新DOMで先に入力、繰り返しcapture/差し替え、別列分離、復元を回帰試験。既存の折りたたみ/復元・モード切替・ルート切替の全体テストも実施。

実Chromeの操作や実送信は行っていない。ユーザーが見た再表示場所は未確認であり、会話本文・履歴の二重表示や、文書再読み込み前に何の変更通知も得られなかった別経路の解消は保証しない。バックアップには送信済みの可能性がある文字も残るが、自動的には入力欄へ戻さない。利用フォルダー適用・push・mergeは未実施。版番号は配布していないため変更しない。

## 追加QA: 本人による回収

基点版の `draftBackups` はセッション／永続スナップショット／名前付きグループで保持される一方、設定画面には回収UIがなく、従来の「設定メニューで確認」案内は不適切だった。ローカル候補では既存タブ一覧の各対象行へ折りたたみ式の「退避テキスト」を追加。番号選択、読み取り専用コピー欄、コピー操作のみで、比較画面・自動挿入は追加しない。コピー権限エラー時は手動選択にフォールバック。閉じた列からの古い操作は拒否。

JSONスナップショット復元後とグループマージ後に回収UIへ届く統合テスト、複数行文字、別列・新しい入力保持、コピー失敗、削除済み列の参照を試験。既存の永続ストレージ／再起動／グループ保存復元テストでもバックアップ保持を検証。保存自体が失敗した場合や、列を閉じた後の通常履歴からは保証しない（通常履歴は意図的に下書きを含まない）。実ChromeのUI・クリップボード操作は未確認。
